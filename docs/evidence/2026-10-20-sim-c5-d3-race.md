## Cause, shown by a trace

A scratch copy of `steps-a.mjs` (not the locked file) sampled Orion's pane every 16 ms right after D3's panel render (`panelText`):

- 10 of 12 runs: `0ms agenda present, focus Orion, scrollY 7323` -> `16ms pane gone, focus Keystone Medical, scrollY 7323`.
- 2 of 12: scrollY 759, pane stayed.

On load the tracker opens Today and scrolls to the beat remembered in day prefs (Keystone Medical, saved by an earlier setup step).
D3 sets `ui.todayFocusId` to Orion and re-renders, but does not scroll. Within one frame the Today scroll observer
re-focuses the beat on screen (`setTodayFocus`), and the three-pane pool (`syncDayPool`) swaps Orion's pane out.
D3 reads the agenda in a second `ctx.ev` a few ms after the render, so it usually wins the race to that frame, but not always.
The tracker is behaving as designed (focus follows what is on screen); the race is in the sim step.

## Candidate fix (locked file: needs Ian's words)

Render inside the same evaluate that reads the agenda, as two other Part A steps already do (steps-a.mjs, near lines 247 and 261):

```diff
     const info = JSON.parse(await ctx.ev(`(async () => {
       window.__clip = null; navigator.clipboard.writeText = t => { window.__clip = t; return Promise.resolve(); };
       const c = DATA.customers.find(x => x.name === ${JSON.stringify(ORION)});
+      ui.view = 'today'; ui.openCustomerId = null; ui.todayFocusId = c.id; render();
       const pane = document.querySelector('.day-pane[data-day-holds="' + c.id + '"]');
```

## The five "must hold" items

1. Sent is never sent twice: c5a (`buildPushRequest` skips a sent item); c5b (`applyPushResults` never rewrites a sent item); probe
   step "Retry/Send again": the request body for the first send is exactly A,B (D already sent absent), and after everything is
   sent a further Send makes no request.
2. A failed push stays retryable with its error visible: probe: B (forceFail) is `failed` with "fake failure (forceFail)", rendered
   with a Retry button for B only; Retry sends only B; a repeat failure keeps it failed; after the cause is cleared Retry sends it.
3. Partial success per item: probe: one POST, A `sent`/`FAKE-A`/stamped, B `failed`, D byte-identical; stored book reflects it.
4. Nothing sent without an externalId: c5b (`sent` with null id stays queued); probe: a `sent` result with no id leaves E queued.
5. Offline fallback: probe: with no connector there is no Send button, `sendGainsightQueue` fetches nothing, and
   `buildGainsightBatchText` still produces the paste text; configured-but-offline shows "Connector offline" and the queue is
   byte-identical.

- Retry shows on every failed row, even if the connector setting was since removed (offline, it only toasts). A failed item can only
  come from a connector push.

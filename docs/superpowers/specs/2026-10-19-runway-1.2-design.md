## 3. Design

### 3.1 CSAT import, pure part (CI-1)

`buildCsatImportPlan(rows, customers, opts)`, pure, no DOM, no storage, no network.

- Header check: the five column names, case-insensitive, any order; otherwise one error "This isn't a CSAT export (missing <names>)".
- Skip list: `CSAT_SKIP_IDS = ['0014000000YgdVaAAJ']` (WF Test), listed as "Skipped: test account".
- Bad row: sent date not a real ISO date, or a year before 2000, or a bad answered date: listed "Skipped: bad date", not applied.
- Match, per row, in order; a step that hits exactly one customer wins:
  1. `c.salesforceId` (new field, 3.3) equals the 18-char ID; or, when either side is 15 chars, the first 15 chars are equal (case-sensitive).
  2. `c.gainsightId` equals the 18-char ID or its first 15 chars (an ID Ian typed into the combined box).
  3. `c.gainsightId` equals `GAINSIGHT_COMPANY_ID`.
  A step that hits two or more customers: the row is listed "Ambiguous" and skipped. A customer hit by two or more rows: all those rows listed "Conflict" and skipped. Names are never used for matching.
- Name suggestions ("Suggest, you confirm"): for a customer with empty `salesforceId` and empty `gainsightId`, and a row not matched above, suggest the pair only when `normalizeCustomerNameKey` of the row's COMPANY_NAME equals the customer's, and that key belongs to exactly one unmatched row and exactly one such customer. Coupang, Inc. and Coupang, LLC have different keys, so each can only pair with its own account. Suggestions are unticked; nothing about them changes unless ticked.
- Update rule per matched pair (ISO strings compared):
  - Runway sent empty: set sent; set answered only if the CSV has one (never clear an answered date Runway has).
  - CSV sent newer: set both from the CSV, answered may become empty ("new survey").
  - Same sent: fill answered only when Runway's is empty and the CSV's is not.
  - Runway sent newer: no change, listed "Runway is newer".
- Output: `{matched, changes:[{customerId, name, field, from, to}], unchanged, runwayNewer:[], unmatchedRows:[], notInFile:[], ambiguous:[], conflicts:[], suggestions:[], skipped:[]}`. Every row lands in exactly one list (matched, unmatchedRows, ambiguous, conflicts, skipped), so the counts add up to the row count.
- A ticked suggestion is applied as a match and also writes `salesforceId` (the 18-char ID) and, only if `gainsightId` is empty, `gainsightId` = `GAINSIGHT_COMPANY_ID`.

### 3.2 CSAT import, screen (CI-2)

- Settings: "Import CSAT dates (CSV)", file input, reuses `parseCsv` and the 8 MB limit. Opens the dry-run modal.
- Dry-run modal: one line of counts ("211 rows: 140 match, 12 dates change, 60 not in Runway, 1 skipped"), then sections, each collapsible and listing names: Dates that would change (account, field, old -> new); Runway is newer; Possible matches by name (checkboxes); Rows not in Runway; Runway accounts not in the file; Skipped (why). Apply and Cancel.
- Apply: first `exportData()` (downloads the JSON backup; the report names the file), then `markUndoable('CSAT import')`, apply, `saveData()`, then a report modal: updated N accounts, skipped by reason, backup file name. Cancel changes nothing.
- Repeatable: applying the same file twice changes 0 dates the second time; a newer file updates, never duplicates (no account or survey record is ever created). `DATA.csatImport = {fileName, fileModified, appliedAt, counts}` is stored (additive, optional).
- No network: the new functions contain no `fetch`, `XMLHttpRequest`, `navigator.sendBeacon` or `WebSocket`.

### 3.3 Salesforce ID field (CI-3)

- New optional additive field `c.salesforceId`, same contract as `gainsightId` (read through `getIntegration`, written only when non-empty, no schema bump). Details tab: a "Salesforce ID" box under the existing one, whose label becomes "Gainsight ID". The existing box's stored data is unchanged.

### 3.4 Folder watch (CI-4)

- Settings: "Watch a folder for CSAT exports" -> `showDirectoryPicker({mode:'read'})`; the handle is stored in IndexedDB `obm-backup-v1`, store `handles`, key `csat-folder` (no DB version change). "Stop watching" removes it.
- On each open, and on a button "Check now": `queryPermission`. Granted: list files matching `/^csat_runway_export_.*\.csv$/i`, take the newest by `lastModified`; if newer than `DATA.csatImport.fileModified`, build the plan and show one line at the top of Today, beside the pinned line: "New CSAT export (19 Oct): 12 dates would change · Review". Review opens the same dry-run modal. Nothing applies without Apply. Permission "prompt": the line reads "CSAT folder: click to allow" and the click calls `requestPermission`. Denied, or no `showDirectoryPicker` (other browsers): no line; the Settings button still works.
- Test seam: the scan takes a handle-like object, so tests pass a fake folder.

## The change

In `renderBeatPrep` (1.1:12622), inside the "Call prep" block, one new section:

1. **Which transcript.** The newest activity on the account (by date, the same order the tracker uses for "Last touch") for which `activityTranscript(a)` (1.1:2944) returns text. Not only the newest call: if the newest call has no transcript, an older one shows, and its label says how old.
2. **How much.** The closing stretch: the last 30 *speech lines* and every line after the first of them, speaker lines kept. A speech line is a non-empty line that is not a speaker/time header (`Name  00:12:34`), a caption cue (`-->`), a bare timestamp or `WEBVTT`. A transcript with 30 or fewer speech lines shows whole.
3. **How it looks.** A box about 6 lines tall that scrolls, opened at the top of the stretch, text escaped. Above it a label with the session and date ("Session 7 · 14 Oct", or the activity type and date when there is no session number). Below it a "Read the full transcript" link to the account's Activity tab (the existing `data-open-cust` / `data-open-tab="activity"` pattern).
4. **None.** No activity with a transcript: the section is not rendered at all (no empty box, no "none" line). House rule, read in 1.1's `beatOutstanding` comment: "the row hides rather than printing a zero."

The words, the label format, the box's place inside Call prep and its height are Ian's look call, made from the run's captures. Defaults until he rules: after the Call prep heading, before Pending deliverables; label "Last transcript · Session N · date".

`renderBeatPrep` stays a plain `function renderBeatPrep(` declaration (the sim's `OVERRIDE_NAMES`, `breaks.mjs:32`). The closing-stretch cut is a separate named function so it can be unit-tested.

## Rules for the build

- Tests first (red on the parent, green after). Page behaviour is checked by selfchecks (tools/selfcheck.mjs, headless
  Chrome) and test/*.test.mjs; connector by connector/test/*.test.mjs.
- Each html change re-pins the 1.1 sha256 in docs/HOSTING.md and tools/sim/osm-day/verify.mjs C8, and the selfcheck
  --expect count (HOSTING.md, README.txt) in the same commit; README/CHANGELOG/VALIDATION in the same commit as the
  behaviour. Locked sim files (steps-a.mjs, steps-b.mjs, lib/breaks.mjs) do not change.
- Look calls (stale-tab banner wording, "Signals to check" heading, Expansion label, report without health): the PM
  proxy makes them, marked "proxy decided", in one batch with captures opened and checked first.
- $0, no network from code or tests, no credentials, no force flags, no ~/.claude writes (session-rename exception
  only), no publishing, no real book, never read *RESTORE-POINT* files.

## Success criteria (predictions, and what would disprove them)

1. Full suite, connector tests and selfcheck: 0 fail; connector tests rise from 168 by at least 4; selfcheck count rises
   by the new checks and prints N/N with console errors 0 on the file and `--serve site` runs. Disproved by any fail.
2. With the network blocked, the Snowflake fake and `/v1/csat` answer; disproved by any non-loopback fetch attempt.
3. A stale tab's saveData returns false and storage is unchanged; disproved by the red selfcheck staying red.
4. After Step 2: `grep -c "Signals to check"` > 0; no AI prompt text built for a seeded account contains its health
   figure or auto risk level (a test reads the built prompt); the progress report has no Health column. Disproved by
   any of those tests failing, or by a control (old commit) passing them.
5. Sim verify: C5-C8 PASS, C1/C2 unchanged from master. Disproved by a new FAIL.
6. `git revert` of the `v13-step2:` commits alone applies cleanly and the suite stays green (checked once on a scratch
   branch, never pushed).

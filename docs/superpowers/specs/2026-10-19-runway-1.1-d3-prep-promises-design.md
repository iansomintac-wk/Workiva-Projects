## The change

In `renderBeatPrep` (1.1:12653), inside the "Call prep" block, one new section, built by a separate named function so it can be unit-tested:

1. **Which.** The account's open commitments: `openCommitments(c)` (1.1:3485, `doneOn` empty). Both directions (`i_owe`, `they_owe`; `COMMITMENT_DIRECTIONS` 1.1:3469).
2. **Order and cap.** Rank every open one by urgency, across both directions: overdue first (oldest due date first; `commitmentIsOverdue` 1.1:3489), then dated by due date ascending, then undated in stored order. Keep the first 5. Show the kept ones in two groups, "You owe" then "They owe you", each in rank order; a group with none kept is not printed. Ranking before grouping means an overdue "they owe" is never pushed out by five undated "you owe"s.
3. **Each row.** The commitment text, escaped, in its own text node starting with the text (so the D3 break, which strips `SIM-OWE[^<]*` from `renderBeatPanel`'s output, removes it). After it the date cue the Coordination tab uses (1.1:13751): "Nd overdue" in the overdue colour, "due soon" for `commitmentDueSoon` (1.1:3490), else "due <date>", undated rows show no date.
4. **More.** More than 5 open: a line "<N> more — see them all" linking to the account's Coordination tab (the `data-open-cust` / `data-open-tab="coordination"` pattern), copied from Pending deliverables' "N more outstanding" line (1.1:12666).
5. **None.** No open commitments: the section is not rendered (no heading, no "none" line), as the D2 transcript box does.

Placement default: right after Pending deliverables, before "Time on your calendar".

`renderBeatPrep` stays a plain `function renderBeatPrep(` declaration (`OVERRIDE_NAMES`, `breaks.mjs:32`). The D2 unit test (`test/d2-prep-transcript.test.mjs:78`) loads `renderBeatPrep` into a vm with a fixed list of functions, so the new function (and any helper it calls) must be added to that list or that test breaks; the plan lists this as an expected break fixed in the same task (assumed until the plan's rehearsal shows it).

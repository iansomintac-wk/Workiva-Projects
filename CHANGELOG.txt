1.0 — August 6, 2026. First working prototype.

  The tracker and its onboarding guide, bundled and validated together for the
  first time as a single release rather than a running build.

  THE TRACKER. A single-file book of business held in browser storage.

    - Today, built as ONE timeline whose axis is the workday. Calls are the
      day's fixed points, ranked work fills the gaps between them, and admin
      collects into a close that pushes to Gainsight in one go. An account gets
      exactly one beat, carrying every reason it surfaced. An optional per-call
      clock time turns the day into real minutes; without it the movements stay
      ordinal and claim no time the book does not have.
    - Accounts in four lenses over one book — list, table, kanban, gantt — with
      a per-account runway strip, domain assessment, session logging, stage
      history, and a graduation model with projected and target dates.
    - Risk and health scoring driven by one signal registry (SIGNAL_DEFS)
      rather than hand-wired rules, with keyword signals that age out, domain
      scores that read as unassessed rather than zero, and open risks carrying
      an executive summary and inline next steps.
    - An AI Copilot layer: four-lens account reads, call prep, routing, and
      suggested next actions. Requires an Anthropic API key entered in
      Settings; every other feature works offline.
    - Gainsight CSV import with value weighting and renewal pressure, and a
      Gainsight sync queue. The queue has no transport — it is a staging list
      you work from, not an integration.
    - (A dated record of time saved shipped here and was retired afterwards; see
      Trim A5.)
    - Automatic backup to a file you choose (File System Access API), plus
      Export/Import JSON. See README.txt for the honest limit on "automatic".
    - Single-level undo, Quick log, deep-linking into the right account tab,
      a Coordination tab, a Handoff tab (PROVISIONAL field set), and a
      Progress Report export.
    - 428 self-checks, run by tools/selfcheck.mjs (the suite was inline in the tracker
      at this point; it moved to tools/selfchecks.js at A1).

  THE GUIDE. A companion onboarding and competency guide covering the tracker
  end to end, with a guided and a quick path, a practice mode, a challenge, and
  a self-reported launch checklist. It stores its own progress in its own
  storage keys and never touches the tracker's book. 18 self-checks:
  window.runGuideSelfChecks().

  KNOWN OPEN ITEMS AT 1.0.

    - The Handoff field set is PROVISIONAL. It is a product open question, not
      an oversight.
    - The Gainsight sync queue has no transport.
    - (Impact minutes were an editable assumption; retired with the time-saved
      record, see Trim A5.)
    - The Progress Report is a snapshot, not a live view.
    - Automatic backup costs one click per session, not zero.

Curriculum piece 1 — stable ids for sessions and deliverables (merged to
master 2026-09-30, with the review fixes and follow-ups M1r, M2r).

  Evidence, notes and runbooks used to hang off a session's NUMBER and a
  deliverable's WORDING, so deleting session 2 or rewording a line silently
  detached ticks and moved notes onto the wrong session. Sessions and
  deliverables now carry ids and everything keys on those.

    - Settings has a per-row deliverable editor: reword a line, reorder it,
      add or remove one. Rewording keeps the line's evidence.
    - Sessions can be reordered. Notes, authored runbooks and evidence stay
      with the session, not the position. Logged calls (activities) still
      match by session number, so deleting or reordering a session moves its
      calls to whichever session now holds that number. That is pending a
      decision (M1) and has not been changed.
    - Deleting a session asks first and says how many accounts have evidence
      on it.
    - Schema 13. Opening an older book migrates it in place: no verdict
      changes, every placeable tick is stamped, numbered notes move to their
      session. Ids survive Export JSON, Import JSON and the file backup. An
      import with malformed ids is rejected rather than repaired, because
      repairing would orphan its evidence.
    - 389 self-checks (was 369).
    - Export JSON before first opening this build on a real book: schema 13
      is not readable by an older build.

Graduation plan — goals, gates, graduation confirm (schema 14).

  Graduating used to mean "the sessions are done". It now means the customer's
  goal was judged, and the One Document says so.

    - Schema 14. Opening an older book migrates it in place: every account gets
      an empty goals list, no exit and no graduation marker; the per-module
      gate defaults are added to config. No verdicts or exits are invented for
      accounts that graduated earlier. Export JSON before first opening this
      build on a real book: schema 14 is not readable by an older build.
    - Goals and gates. A primary goal on the Overview tab, with readiness gates
      copied in from the module's defaults and editable per account. Financial
      Reporting and GRC had NO default gates when this shipped (superseded by
      schema 15 above); a goal with an empty list is judged by verdict alone
      and the panel and the packet read "0 gates".
    - Change goal. The old goal closes as replaced and keeps the reason; only
      done gates with identical wording carry over. New signal goal_changed
      asks you to confirm the target graduation date, and clears once marked.
    - Graduation confirm. A verdict and note are asked for. "Met" with open
      gates prompts for a reason and never blocks. A graduation with no goal
      needs the explicit "no goal recorded" choice or a new goal. New signal
      ready_to_graduate (target date set and all gates done, or verdict met).
    - Early exit. Graduating with planned sessions unheld asks for an exit
      reason and records those sessions as not needed; every tally and bar then
      reads held of held (5/5). One action, one save, one Undo step.
    - One Document. The knowledge-transfer packet opens with a GOALS section:
      goal, verdict, gates, criteria, any change with its reason, the early
      exit, the check-back. "No goal recorded." and "Graduated before goal
      tracking." are told apart.
    - Success Plan items in the Gainsight queue for goal created, changed and
      verdict. The queue still has no transport; nothing is sent.
    - Settings -> Graduation gates: the default gates per module and goal type.
    - 436 self-checks (was 389). New: tools/graduation-scenarios-seed.js, six
      end-to-end scenarios run headlessly; tools/selfcheck.mjs takes a
      comma-separated --seed list and a --verbose flag.

Development history
-------------------
This build came out of a long prototyping run. The version-by-version record of
that run — every change, and the reasoning behind individual lines — is archived
in docs/history/:

  docs/history/CHANGELOG-prerelease.txt   the full development changelog
  docs/history/VALIDATION-prerelease.txt  every validation pass during the run

Comment markers such as "v72" or "v91" throughout the source point into that
archive. They are provenance, not a version scheme.

Schema 16 (task C-1, connector groundwork).

    - Schema 16. Opening a schema 15 book rewrites each queued Gainsight item
      to carry status (queued, sent or failed), fields, externalId, sentAt and
      error; an old prose-only item opens as queued with empty fields. A sent
      item keeps all of them through export and import. Nothing is sent yet.
    - Activities may carry an optional Gong call link (gong) and accounts an
      optional Gainsight pull record (gainsight). Neither is created for
      existing records; when present they are cleaned on import (a javascript:
      link is dropped, a Gong summary is capped at 4,000 characters, a call
      summary never overwrites the activity's own summary).
    - Stakeholders have an optional email on the Coordination tab. It is kept
      through export and import. Existing stakeholders gain none.
    - Export JSON before first opening this build on a real book: schema 16 is
      not readable by an older build.

Connector client (task C-2).

    - Settings has a Connector block: the address of the connector (this computer only) and its token, with a Check
      button. The header shows "Connector offline" quietly when it is not running, "Connector: FAKE DATA" whenever it
      reports made-up data, and "Connector: connected" otherwise. It is checked when the tracker opens (only if a
      connector is set up), on Check, and on Save; never on a timer.
    - With a connector set up, every AI feature goes through it and the key stays in the connector. If the connector is
      not running the tracker falls back to a browser AI key when there is one. A length-cut AI reply still shows the
      same notice. Without a connector the tracker works exactly as before.
    - 443 self-checks (was 434).

Check for calls (task C-3).

    - With a connector set up, the header has Check for calls. It lists recorded Gong calls since you last added some,
      matched to your accounts by Gainsight id, then exact account name, then a stakeholder's email (an ambiguous match
      is left for you to pick). Nothing is added until you tick a call and click Add; each becomes an activity linked to
      its Gong call, with your title as the summary. Without a connector the button is not shown; with one that is not
      running you get a plain "Connector offline" message and nothing changes.
    - Fixed (G06): choosing Email, Partner Sync or Implementation Note in the log form now clears and locks Session #,
      and the save forces no session for those types. Before, the form pre-selected the next session for an Email. The
      same rule holds for calls added from Gong: an email-kind call is an Email and never takes a session number.
    - 448 self-checks (was 443).

Refresh from Gainsight (task C-4).

    - With a connector set up, the header has Refresh from Gainsight. It compares the Gainsight accounts that carry a
      Gainsight id you already have with the tracker, showing "Gainsight says X, tracker has Y" for tier, ARR, renewal
      date, CSM owner and contacts, and offering to mark a gate done when Gainsight shows it done. Nothing changes until
      you tick a row and click Update. Ticked tier, ARR and renewal date overwrite that field, ticked contacts only add
      new people, the CSM owner is shown only, and stage, goals, verdicts, notes and scores are never written. Without
      a connector the button is not shown; with one that is not running you get a plain "Connector offline" message.
    - 452 self-checks (was 448).

Send to Gainsight (task C-5).

    - With a connector set up, the Gainsight queue has a Send to Gainsight button. It sends only unsent items and marks
      each by the connector's answer: sent shows the Gainsight id, failed shows the error and a Retry button. A sent
      item is never sent twice and nothing is marked sent without an id from the connector. With no connector, or one
      that is not running, nothing is sent and the copy-and-paste text and JSON export still work.
    - Queued items carry structured fields for their kind. The day close counts "Sent to Gainsight today" from the
      queue and keeps failed items in "what you queued".
    - The queue's "no transport" wording now says so only when no connector is configured.
    - 455 self-checks (was 452).

Brief my day (task C-6, ruling R4).

    - With an AI key or a connector set up, Today has a Brief my day button. It asks the AI for one next action and
